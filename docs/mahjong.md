# 血流红中：当前规则与接入说明

本文件对应规则版本 `bloodflow-red-v1`，以 `src/mahjong-engine.js` 的 `MAHJONG_RULES` 及结算实现为准。这是一套固定、可复核的四人玩法；房间可调整底分、带入金额和练习模式，不能单独调整番型、定缺或封顶。

## 入口与房间流程

门户川麻入口进入 `/mahjong/`。页面与德州、老虎机共用账号、顶栏个人中心、钱包和财富榜。“我的进行中”通过 `game: 'mahjong'` 区分麻将桌，邀请链接为 `/mahjong/?room=<房号>`。

1. 登录后创建正式房，或输入房号加入现有正式房。默认底分 10、带入 2,000；底分必须为 1–1,000 的整数，带入金额必须为底分的至少 16 倍且不超过 1,000,000。
2. 正式房满四人、全部在线、有筹码且准备后自动开局。房间进行中不能插入新玩家。
3. 第一局庄家为 0 号位，之后按座位轮换。庄家起手 14 张、其余玩家 13 张，从庄家出牌开始。
4. 依次摸牌、出牌和响应碰杠胡。一次出牌可能有多人能胡；服务器等待全部候选人的选择或超时，再统一结算。胡牌优先于碰杠；无胡牌时按出牌者下家起的座位顺序处理碰杠请求。
5. 胡牌后继续参与，直到牌墙耗尽或有人筹码归零。本局结束后展示结果，并要求四位玩家重新准备。房间不自动倒计时开下一局。
6. 练习房会自动加入小竹、阿川、红豆三位明确标识的电脑陪练，真人准备后即可开始。练习房不接收其他真人加入，也不接入正式钱包或战绩。

同一个账号同时只能有一个麻将座位。再次加入自己的房间等同恢复座位；在其他页面恢复时，旧页面失去操作权。

## 牌组与胡牌

| 项目 | 实现规则 |
| --- | --- |
| 牌组 | 万、筒、条各 36 张，加 4 张红中，共 112 张；不含其他字牌或花牌 |
| 红中 | 胡牌计算时作为赖子代替所需牌；可以打出，也可被其他玩家胡；不能碰杠 |
| 开局规则 | 不换三张、不定缺 |
| 吃牌 | 不允许 |
| 普通胡牌 | 四组顺子或刻子，加一对将；已碰杠的副露计入组合 |
| 特殊胡牌 | 支持七对；其他未列出的特殊牌型不额外识别或计分 |
| 连续胡牌 | 点炮胡后保留原有手牌继续参与；自摸胡后仍要出牌，同一次摸牌不能再次自摸胡 |
| 多人胡牌 | 支持一炮多响；收到一个人的响应不会抢先取消其他人的胡牌机会 |
| 抢杠胡 | 允许抢补杠；抢杠成功时保留原碰牌，不支付补杠分 |

红中本身不加倍。系统不实现四红中直接胡、红中数量奖励、杠上花额外加番、十三幺等附加规则。红中作赖子的具体分组由胡牌判断完成，公开记录保留实际红中牌，不把红中换成虚构的牌面。

## 番型与付款

这里使用直接的“倍数”，不是把显示数字再做二次幂运算。

| 组合 | 倍数 |
| --- | ---: |
| 平胡 | 1 |
| 对对胡 | 2 |
| 七对 | 4 |
| 清一色平胡 | 4 |
| 清一色对对胡 | 8 |
| 清一色七对 | 16 |

基础牌型取七对、对对胡或平胡之一；清一色在此基础上乘 4，总倍数封顶 16。清一色检查手牌及副露中的实际花色，红中不增加额外花色。

- 自摸：其他三家分别支付 `底分 × 胡牌倍数`。
- 点炮或抢补杠胡：出牌者向每位胡牌者分别支付 `底分 × 该赢家的倍数`。
- 暗杠：其余三家分别支付 `2 × 底分`。
- 补杠：其余三家分别支付 `1 × 底分`。
- 直杠：出牌者支付 `2 × 底分`。
- 剩余牌墙没有补牌时不能杠。胡牌和杠牌都逐笔记账，不收取抽水。

例如底分 10 时，自摸清一色平胡为三家各付 40、胡牌者合计获得 120；点炮七对由点炮者支付 40。若同时点给平胡和七对，正常应分别支付 10 和 40。

每个付款人的赔付上限是自己当时的桌上筹码，不能负债或透支钱包。多位赢家同时向同一人收分、且付款筹码不足时，先按应得比例向下取整，再把不足一筹码的余数按付款者下家起顺时针逐个分配。一次结算只分配实际支付的筹码，四家变动之和必须为零；有人结算后筹码归零，本局立即结束。

例如上例点炮者只剩 23，平胡和七对先按 10:40 分为 4 和 18，余下 1 按顺时针赢家顺序分配。不会把 23 以外的钱从其钱包自动扣出。

牌墙摸完后不查叫、不查花猪、不退杠分。已经完成的胡牌和杠牌输赢保留。

## 钱包、战绩与隐私

正式桌入座从共用钱包扣除带入金额，在麻将座位托管中保存相同金额。之后胡牌和杠牌只改变桌上筹码；离桌时将剩余桌上筹码退回钱包。带入和退回是内部转移，不计入游戏盈利。

| 数据或流水 | 用途 |
| --- | --- |
| `mahjong_rooms` | 完整可恢复房间，包含牌墙、私有手牌、待响应选择、行动版本与定时截止时间 |
| `mahjong_seats` | 每次入座的独立 `entryId`、托管余额、练习标记及已退款标记 |
| `mahjong_events` | 每次胡牌或杠牌的唯一事件与公开结算内容 |
| `mahjong_rounds` / `mahjong_round_players` | 已完成正式局的公共结果与参与者个人统计 |
| `BRING_IN` / `CASH_OUT` | 真正增减可用钱包；以 `mahjong-seat` 和本次 `entryId` 防止重复转账 |
| `MAHJONG_SETTLE` | 桌内输赢备忘；以 `mahjong-event` 和事件 ID 防重，不再次加减可用钱包 |

每次动作在一个 SQLite 事务中保存房间、座位余额、新结算事件、相关流水及完成局战绩，提交成功后才广播和返回成功。事务失败时不更新已公开的房间状态。正式桌筹码变化必须有新的守恒结算事件，不能通过重复保存旧快照改变余额。

财富榜与总资产包含可用钱包、德州桌上筹码以及所有尚未退款的正式麻将筹码。等待本局结束后离桌的筹码仍计入资产，不能因此绕过每日补助门槛。练习房不计入钱包、排行榜或个人战绩。

个人中心有独立“麻将”页签，按每页 20 局展示：时间、房间、底分、起始与结束筹码、净盈亏、胡牌次数，以及可展开的胡牌/杠牌明细。总览和后台接口增加 `mahjongRounds`、`mahjongNet`、`mahjongHuCount`；合计净盈亏包含已完成的德州、麻将和老虎机记录。正在进行的麻将局内输赢可以通过筹码明细查询。

客户端只收到自己的当前手牌。其他人的未公开手牌、牌墙、待响应动作选择不在公共房间状态或历史 API 中。暗杠牌面默认隐藏，直到其作为胡牌组合被合法公开；战绩展示当时已经公开的赢家实际牌组。

## 超时、离桌与重启

- 默认真人摸打与碰杠胡响应窗口均为 20 秒。电脑、主动托管和离线玩家的默认自动行动延迟为 750 毫秒；切换托管不会延长已经进行中的响应窗口。
- 自动行动优先胡牌，响应时不胡则过；自己的回合根据自己的手牌保留红中、顺子、刻子、对子和搭子，优先打出孤张；没有副露时也会考虑七对方向。同等价值时可以打出新摸的牌。当前托管与陪练不主动碰杠，也不读取别人的暗牌或牌墙。
- 对局中断线立即标记离线并进入托管，座位保留到本局结束或本人重连；不是德州的 90 秒离线宽限规则。未开局或已结算时断线，立即退回剩余筹码并清理座位。
- 对局中点“离桌”会标记“本局结束后离桌”并托管；当前筹码继续承担输赢。结算后退款，等待状态下点离桌则立即退款。取消托管或重新恢复座位也会取消待离桌标记。
- 管理员封禁时断开账号连接；进行中的麻将座位托管到本局结束后退款，不能抽走本局的赔付筹码。
- 停机时清除运行中的定时器、保存当前房间。重启后按数据库恢复同一副牌墙、手牌、已完成事件、未完成响应与筹码，不作废正在进行的麻将局。
- 恢复后先给尚待行动者一个正常窗口（默认 20 秒）重连，之后没有回来的玩家继续托管；原本已结束或未开局的离线座位会退款清理。恢复后进行中的一局完成时，仍离线、待离桌或已经归零的真人座位会退回并清理。

数据库需随部署持续保留。当前为单 Node.js 进程：内存房间和 Socket 所有权由该进程管理，SQLite 负责持久化；不能让多个进程同时接管相同数据库里的牌局。

## 牌面与动效

牌面使用本地 SVG 素材：筒子圆点、条子竹节、一条小鸟、万子和红中；手牌、弃牌、副露及公开战绩共用同一套素材。手机竖屏手牌分两行，横屏与电脑保留一行。

新局发牌、摸牌、出牌与碰杠胡使用短动效，结算时显示筹码变化并强调赢家。飞牌、字效和礼花在独立的不可点击图层里播放，状态和可选操作始终按服务器结果立即更新，不等待动画结束。其他玩家的摸牌只显示牌背；出牌飞行只使用已经公开的牌。

初次打开进行中的牌局、断线重连和重复状态不会重播旧动画。切到后台、窗口尺寸改变或离开牌桌时清理动效；开启系统“减少动态效果”时使用静态展示。

## HTTP 与 Socket.IO 接口

麻将与现有游戏使用相同监听端口，页面为 `/mahjong/`，Socket.IO 命名空间为 `/mahjong`。握手使用 `auth: { token }`，令牌沿用平台注册、登录响应；不通过客户端传入的账号 ID 决定钱包归属。

| HTTP 接口 | 说明 |
| --- | --- |
| `GET /api/mahjong/rooms` | 公共麻将房间摘要 |
| `GET /api/mahjong/rules` | 固定规则版本与说明 |
| `GET /api/me/mahjong?page=1` | 当前账号的已完成正式局战绩，需 Bearer 登录令牌 |
| `GET /api/me/tables` | 包含麻将的“我的进行中”，麻将条目 `game` 为 `mahjong` |
| `GET /api/me/overview` | 共用资产和各游戏战绩摘要 |
| `GET /api/me/ledger?page=1` | 包含麻将转账与桌内输赢的流水 |
| `GET /api/leaderboard` | 共用财富榜 |
| `POST /api/me/subsidy` | 登录后按平台总资产门槛领取每日补助 |

| 客户端事件 | 参数 |
| --- | --- |
| `room:list` | `{}` |
| `room:create` | `{ base, buyIn, practice }` |
| `room:join` / `room:resume` | `{ code }` |
| `room:ready` | `{ ready: boolean }` |
| `room:trustee` | `{ enabled: boolean }` |
| `room:leave` | `{}`；响应中 `pending` 表示是否待本局结束退款 |
| `game:action` | `{ requestId, roundId, turnId, action, tile? }`，动作包括 `discard`、`peng`、`gang`、`hu`、`pass` |

事件回调统一返回 `{ ok: true, ... }` 或 `{ ok: false, error }`。服务端发送 `lobby:state`、按查看者过滤的 `room:state`、`room:left` 和 `session:replaced`。

`requestId` 是 8–100 字符的独立动作编号；服务端保存最近 256 个已处理请求。重复相同动作返回已有结果，不重复行动；同一编号不能改成其他动作。`roundId` 和 `turnId` 防止旧页面操作新局；同一张出牌的多个待响应者允许使用各自在该响应窗口内看到的版本，其他人先回复不会使合法的一炮多响失效。

## 文件与验证

- 规则：`src/mahjong-engine.js`；只接受合法行动，使用服务器随机源洗牌。
- 房间与连接：`src/mahjong-service.js`；运行中定时器和 Socket 不放进规则状态。
- 持久化：`src/mahjong-store.js`；复用 SQLite 及共用钱包流水。
- 页面：`public/mahjong/`；门户和个人中心分别由现有 `portal.js`、`account.js` 接入。
- 测试：`test/mahjong-engine.test.js`、`test/mahjong-store.test.js`、`test/mahjong-service.test.js`、`test/mahjong-effects.test.js`，以及共用账号、钱包、老虎机和后台回归测试。

运行 `npm test` 检查完整回归。服务端测试可通过 `createPokerServer` 的 `mahjongTurnTimeoutMs`、`mahjongBotDelayMs` 缩短等待；这些是程序配置参数，不是房主可调整的玩法设置。现有部署入口 `deploy/serve.js` 直接加载 `server.js`，无需新增端口、服务或依赖。
